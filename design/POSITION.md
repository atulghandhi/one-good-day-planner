# One Good Day — Position

## Thesis

Most planners help you do more. This one helps you choose less and feel okay
about it.

## Aesthetic position

One Good Day is an editorial, soft-modern daily planner.

- **Type does the heavy lifting.** Fraunces for emotion, Plus Jakarta Sans for
  utility. The page reads like a quiet column, not a dashboard.
- **Colour is atmosphere, not personality.** Gradients drift; cards stay calm.
- **Motion is calm and choreographed.** A handful of named moments
  (intro, MIT done, day's end) have rehearsed timing. Everything else is still.
- **Playfulness is an Easter egg, not a vibe.** Kirby, confetti, glitter are
  opt-in via theme. They are never the first impression.

## Reference apps (in order of influence)

1. **Craft** — typographic restraint, editorial calm.
2. **Arc** — choreographed moments, theme-as-release, branded surfaces.
3. **Linear** — opinionated keyboard flow, "fast and quiet" pacing.

Explicitly **not** Notion (feature breadth), **not** Duolingo (streaks/gamification),
**not** ClickUp (project management).

## What gets demoted to Easter egg

| Element | New status |
| --- | --- |
| Kirby | Sakura theme only (unchanged). |
| Confetti on substep tick | Removed. Confetti is for the day's win, not every ✓. |
| Big confetti on MIT done | Kept, slightly toned. Paired with screen-wide choreography. |
| Gradient blobs | Lower opacity (30–35%), gentle independent drift. |
| Three-blob layout | Kept — atmosphere, not focus. |

## Explicit non-features (the cut list)

We are not building these. If you are tempted, re-read the thesis.

- **No accounts.** Friction-removal beats sync convenience.
- **No streaks, no scores, no completion %.** These warp behaviour.
- **No tags, projects, multi-list views.** These turn the app into Notion.
- **No notifications** beyond an opt-in end-of-day reflect prompt.
- **No AI summarisation** for the first 6 months. If ever, client-side only.
- **No "team" / collaboration / shared edit.** Solo by design.
- **No drag-and-drop reordering.** It signals "this is a real task manager."
- **No mobile native app.** PWA is enough until users name otherwise.
- **No analytics on user behaviour.** Privacy is part of the resistance-removal
  story.

## Hedges (the things people ask for instead of accounts)

- **Sync via QR / share URL** (Phase 3.1): zero backend, transfer today's
  state between devices by scanning a code.
- **Share card** (Phase 2.3): generate a beautiful image of today's plan for
  social. Marketing surface = product surface.

## Cadence

- **Theme as release.** Ship one new theme per quarter. Each theme has a name,
  a vignette (what is this theme for?), and one new background effect.
- **Design diary.** Public posts explaining each design decision. The act of
  writing forces the discipline.

## How to use this doc

When deciding whether to build something, the only question is:

> Does this reduce the friction of *starting* a day, or does it add work that
> justifies the app's existence?

If the latter, it does not ship.
